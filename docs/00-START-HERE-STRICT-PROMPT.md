# تعليمات صارمة إلزامية — اقرأها بالكامل قبل أي سطر كود

أنت الآن مسؤول عن **إكمال مشروع ERP Lite**. المشروع مبني بالفعل بمعمارية محددة ومُختبَرة فعلياً (SQL حقيقي + HTTP حقيقي، مش نظرياً). مهمتك محدودة بدقة فيما يلي.

---

## 🚫 ممنوعات مطلقة — لا استثناء

1. **ممنوع تعديل أي ملف داخل `/sql/` نهائياً.** الملفات دي اتنفّذت فعلياً على PostgreSQL حقيقي واتختبرت (شركات، RLS، تزامن 30 اتصال). لو لقيت "خطأ" فيها، **الاحتمال الأكبر إنك مش فاهم القرار المعماري وراها** — اقرأ `BACKEND_ARCHITECTURE.md` و`ERP-Lite-CHANGELOG.md` الأول قبل ما تفكر تغيّر أي سطر SQL.

2. **ممنوع تعديل أي ملف داخل `/erplite-backend/app/` إلا في حالتين فقط:**
   - إصلاح قسم "⏳ Remaining" المذكور صراحة في `ERP-Lite-CHANGELOG.md` (مثال: `created_by` وهمي في بعض الـ endpoints).
   - إضافة Endpoint **جديد** (مش تعديل موجود) مطلوب فعلياً للفرونت إند (مذكورين في قسم 11 من `ERP-Lite-Frontend-Specification.md`).

3. **ممنوع تغيير أي اسم جدول، اسم عمود، أو بنية Response من أي Endpoint موجود حالياً.** لو الفرونت إند محتاج شكل بيانات مختلف، الحل في الفرونت إند (تحويل البيانات بعد الاستلام)، مش في تغيير الـ API.

4. **ممنوع تعديل `app/core/database.py` أو `app/core/dependencies.py` نهائياً.** دول قلب نظام RLS الأمني — أي تعديل فيهم غير مفهوم تماماً = خطر تسريب بيانات بين الشركات.

5. **ممنوع حذف أو "تبسيط" أي Business Rule check موجود في أي `service.py`** (زي `BR-SAL-009`, `BR-ACC-001`, إلخ) حتى لو بدت لك "زيادة تعقيد". كل قاعدة منهم مكتوبة عمداً ومربوطة بمستند قرار عمل موثَّق.

**لو حسّيت إن في حاجة في الباك إند "لازم تتغيّر" عشان الفرونت إند يشتغل صح، دي مش قرار تاخده لوحدك — وقف واكتب في ملف `QUESTIONS.md` جديد وسيبه لحد ما صاحب المشروع يراجعه.**

## ✅ مهمتك الوحيدة: بناء الفرونت إند

اتّبع الترتيب ده بالحرف الواحد، من `ERP-Lite-Frontend-Specification.md` قسم 10:

1. **البنية الأساسية:** Login + Layout + Sidebar + Auth Context (JWT في localStorage أو httpOnly cookie، تجديد عند انتهاء الصلاحية).
2. **المبيعات كاملة** (Customers + SalesOrders) — ابدأ بيها لأنها أكتر جزء مُختبَر في الباك إند.
3. **المشتريات** — نفس قالب المبيعات حرفياً (نفس التخطيط، نفس منطق البحث والفلاتر).
4. **المخزون** (Items + Stock Balance).
5. **المحاسبة** (Chart of Accounts + Journal Entries).
6. **Dashboard** — آخر حاجة.

**كل شاشة موصوفة بالتفصيل (الحقول، التحقق، التخطيط) في `ERP-Lite-Frontend-Specification.md` — اتبعها حرفياً، متخترعش تصميم بديل.**

### التقنية الإلزامية
React 18 + TypeScript + React Router + TanStack Query + react-hook-form + Zod. **عربي RTL بالكامل.**

### القاعدة الذهبية للتعامل مع الـ API
- استهلك الـ Endpoints الموجودة زي ما هي بالظبط (راجع `/docs` على السيرفر الشغّال، أو `BACKEND_ARCHITECTURE.md` قسم 4: **كل مسار API بيستخدم `uuid` بس، مفيش `id` رقمي داخلي أبداً**).
- أي خطأ 422 من الـ API معناه قاعدة عمل اتخالفت — اعرض رسالته للمستخدم زي ما هي (الرسائل مكتوبة بوضوح ومربوطة برقم القاعدة، مثال: `[BR-SAL-009] Customer is suspended`).
- خطأ 409 معناه تعارض تعديل (Optimistic Locking) — أعد تحميل البيانات تلقائياً وأعلم المستخدم.

## قبل ما تبدأ أي سطر كود

1. اقرأ `HOW-TO-FINISH-BACKEND.md` وشغّل الباك إند فعلياً محلياً (SQL + uvicorn) وتأكد إنه شغال (`/health` يرجّع 200).
2. جرّب التسلسل: شركة → مستخدم → لوجين عبر `/docs` يدوياً، تأكد إنك فاهم شكل الـ Request/Response لكل Endpoint قبل ما تكتب أي كومبوننت.
3. اقرأ `ERP-Lite-CHANGELOG.md` كاملاً — فيه كل حاجة اتعملت واتختبرت، وكل حاجة ناقصة.
4. بعد كده بس، ابدأ الفرونت إند بالترتيب المذكور فوق.

**أي التزام بالبنود دي مش تفاوضي. الأولوية القصوى: لا تكسر حاجة شغالة ومُختبَرة.**
