# ERP Lite Frontend — دليل التشغيل

## التشغيل المحلي
```bash
cd erplite-frontend
npm install
cp .env.example .env   # عدّل VITE_API_BASE_URL لو الباك إند شغّال على عنوان مختلف
npm run dev
```
افتح `http://localhost:5173` — سجّل دخول بأي مستخدم اتعمل عبر `POST /security/users` في الباك إند.

## الحالة الحالية (مبني ومُختبَر: TypeScript compile ✅ + npm run build ✅ + سيرفر شغّال ويرجّع HTML صح ✅)

**ملحوظة مهمة:** الاختبار في هذه الجلسة اقتصر على البناء (Build) والتشغيل الأساسي — لم يُختبَر تسجيل الدخول والتدفق الكامل عبر متصفح حقيقي متصل بالباك إند الفعلي (بعكس الباك إند اللي اتاختبر end-to-end كامل). **أول خطوة لازم تعملها:** شغّل الباك إند + الفرونت إند مع بعض، وجرّب تسجيل الدخول فعلياً بعينك.

### شغّال ومكتمل
- تسجيل الدخول (`/login`) + حفظ التوكن + توجيه تلقائي عند انتهاء الصلاحية (401)
- Layout كامل (Sidebar + حماية المسارات)
- **موديول المبيعات كامل:** قائمة عملاء + بحث، نموذج عميل جديد، قائمة أوامر بيع، **نموذج أمر بيع جديد ببنود ديناميكية وبحث أصناف حي (Autocomplete)**، شاشة تفاصيل + زر اعتماد مع معالجة تعارض النسخ (409)

### فجوات موثَّقة (مش سهو)
1. **اختيار العميل في نموذج أمر البيع لسه بـ uuid يدوي نصي** — محتاج `CustomerAutocomplete` بنفس نمط `ItemAutocomplete` بالظبط (الملف الجاهز يُنسخ ويتبدّل فيه `salesApi.listCustomers` بدل `inventoryApi.searchItems`).
2. **العملة مثبَّتة على uuid وهمي** في نموذج أمر البيع — محتاج Dropdown من `GET /core/currencies` (Endpoint موجود بالفعل، مجرد ربط).
3. **باقي الموديولات** (مشتريات، مخزون، محاسبة، لوحة المتابعة الكاملة) — لم تُبنَ بعد، تُبنى بنفس قالب `src/modules/sales/` حرفياً.

### تعديلات أُضيفت على الباك إند أثناء بناء هذه الجلسة (إضافات فقط، بلا كسر أي حاجة موجودة)
- `GET /sales/customers` (قائمة) — كان موجود بس "جلب واحد بالـ uuid".
- `GET /sales/sales-orders` (قائمة، DTO خفيف بدون بنود).
- `GET /inventory/items?search=...` — بحث فعلي بدل الاكتفاء بالتصفح.

كل الإضافات دي **Additive فقط** — مفيش أي Endpoint موجود اتغيّر شكله أو سلوكه.
